What changed and why

36 duplicate or useless indexes removed

Your tables have 76 secondary indexes. Many are created twice under two names (user_id and idx_trades_user_id, status and idx_trades_status) or are the left part of a composite index that already serves the same query. Every extra index slows each insert and update. trades goes from 12 to 7, scrip_ticks_history from 5 to 2.

35 indexes added on real access paths

Lists are filtered by user and sorted by time, so the main pattern is (user_id, time column). Queues get (status, time). Tick-time scans (alerts, GTT, pending paper orders) get (symbol, status, price). support_tickets, notifications, signals and internal_transfers have no index at all today.

7 days in trades, then trades_dump

trades holds every OPEN / HOLD trade plus anything entered or closed in the last 7 days. A daily job moves older final trades to trades_dump. Reads use trades, and add trades_dump only when the range starts more than 7 days back.

Admin reactivation is versioned

When an admin reactivates a CLOSED trade, the same row in trades goes back to OPEN. In the same transaction the old state goes to trades_history, who did it goes to action_logs, and the realised P&L posted at close is reversed in ledger.

One audit table: action_logs

Replaces action_ledger, which only has admin, type, table and free text. action_logs stores actor, role, entity id, old and new values as JSON, reason and IP.

Market data in its own database

scrip_data, scrip_ticks_history (14.4 Cr ids used), lot sizes and ban lists move to market_db so tick writes never compete with trades and ledger. expiry_rules stays: it holds per-user settings.

Roles & permissions (optional step)

roles, permissions, role_permissions, user_roles replace admin_menu_permissions, and give you a trades.reactivate permission. users.role can stay until the app reads the new tables.

Security fixes found in the dump

ip_logins.password_used stores typed passwords: stop writing it and clear it. Kite access_token, PAN / Aadhaar numbers and client bank account numbers are plain text: encrypt them.

Trade lifecycle: reactivation, rotation and reads

Statuses are your trades.status values: OPEN, HOLD, CLOSED, SETTLED, CANCELLED, DELETED. A reactivation runs in one transaction, so trades, trades_history, action_logs and ledger never disagree.

-- 5) Daily rotation after market close: final trades whose entry AND exit
--    are both older than 7 days -> trades_dump. OPEN / HOLD never move.
--    Repeat until 0 rows move; batches of 5,000 keep locks short.
CREATE TEMPORARY TABLE IF NOT EXISTS tmp_ids (id INT PRIMARY KEY);
TRUNCATE tmp_ids;
START TRANSACTION;
INSERT INTO tmp_ids
  SELECT id FROM trades
  WHERE status IN ('CLOSED','SETTLED','CANCELLED','DELETED')
    AND entry_time < NOW() - INTERVAL 7 DAY
    AND COALESCE(exit_time, entry_time) < NOW() - INTERVAL 7 DAY
  ORDER BY id LIMIT 5000
  FOR UPDATE;

CREATE TABLE roles (
  id SMALLINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50) NOT NULL UNIQUE,      -- SUPERADMIN, ADMIN, BROKER, TRADER
  description VARCHAR(255),
  is_system TINYINT(1) NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE permissions (
  id SMALLINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  module VARCHAR(100) NOT NULL,          -- old admin_menu_permissions.menu_id
  action ENUM('view','add','edit','delete','export','reactivate') NOT NULL,
  code VARCHAR(100) NOT NULL UNIQUE,     -- e.g. 'trades.reactivate'
  UNIQUE KEY uq_perm_module_action (module, action)
);
CREATE TABLE role_permissions (
  role_id SMALLINT UNSIGNED NOT NULL,
  permission_id SMALLINT UNSIGNED NOT NULL,
  PRIMARY KEY (role_id, permission_id),
  KEY idx_rp_permission (permission_id),
  FOREIGN KEY (role_id) REFERENCES roles(id) ON DELETE CASCADE,
  FOREIGN KEY (permission_id) REFERENCES permissions(id) ON DELETE CASCADE
);
CREATE TABLE user_roles (
  user_id INT NOT NULL,                  -- INT to match users.id
  role_id SMALLINT UNSIGNED NOT NULL,
  assigned_by INT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, role_id),
  KEY idx_ur_role (role_id),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (role_id) REFERENCES roles(id)
);
